The spec

Every file format in the standard, one page each. Each page says what the format is for, who writes and reads it, what every field means, and shows a file that passes and one that must be rejected.

The key words MUST, MUST NOT, SHOULD, SHOULD NOT and MAY are used as described in RFC 2119 and RFC 8174 when, and only when, they appear in capitals.

Start here

The files a person keeps, the facts they are scored against, a correction to those facts, and the files a group makes.

  • Open Values Passport v0.1 stableA small file that says how much each of ten shared values matters to one person, from 0 to 5, with no name in it.
  • Open Values Lens v0.1 stableA facts file for one kind of choice, such as banking: the criteria options are scored on, and every option with its scores from 0 to 100 and the source for each score.
  • Open Values Lens Patch v0.1 draftA list of corrections to one facts file: changed scores and added options, each with its source.
  • Open Values Collective v0.1 draftA group's values, worked out in the browser by averaging several people's values files.
  • Open Values Slate v0.1 draftA group's plan for one facts file: the options it would use, the ones it would move away from, and the sourced reason for each, worked out from the group's values.
  • Open Values Position v0.1 draftOne person's position on a question: where they stand, how sure they are, the strongest case against it in its holders' own words, and what would change their mind.
  • Open Values Agreement v0.1 draftThe record of what a group agreed: the question, who was there, each agreement with who does it, by when and what counts as done, and what is still open.

Files people or tools write

A file someone writes by hand or with a tool, and keeps.

  • Open Values Citation Bundle v0.1 stableA frozen copy of a facts file, the weights used to rank it and the ranking that came out, so anyone can run the ranking again and check they get the same result.
  • Open Values Lines v0.2 stableThe list of rules a person can choose to hold, such as an allergy, a diet or a company to avoid, plus the published sets of rules that are on by default.
  • Open Values Ontology v0.4 stableThe menu people browse the catalogue by: eight human needs, and the areas of life with their categories, each category tagged with a need and linked to its facts file once one is built.
  • Open Values Errand Registry v0.1 stableA list of everyday tasks, such as the weekly grocery shop, each broken into the categories a person picks from to do it.
  • Open Values Synonym Registry v0.1 stableA list of everyday words people search with, each pointing to the category or tag it means, such as "pop" to the soda category.
  • Open Values Tag Registry v0.1 stableThe list of labels an option can carry, such as Organic or Fair Trade, with the other spellings that count as the same label and a sentence on what each one means.
  • Open Values Asks/Offers v0.1 draftA file of requests for help (asks) and offers of help, such as a library asking for help running a digital-safety session, each pointing at related guides, categories and organisations, with sources.
  • Open Values Attestation v0.1 draftA public record of one person's response to a proposal: support, concern, needs work, oppose or abstain, with a comment.
  • Open Values Challenge Set v0.1 draftWorked examples for showing a reader the best case for a different choice: for a category, a likely weighting and its opposite, the top pick under each, and the sourced facts to show.
  • Open Values Decision Contracts v0.2 draftFor each product or service category on Conscious Consuming, the setup of its decision page: the one-line summary of what to compare, up to three dials a reader can move, whether a budget answer can be shown, and which computed answers to show.
  • Open Values Design Tokens v0.1 draftThe colours, type sizes, spacing, motion rules and small drawings that give an Open Values site its look, grouped into one profile per site.
  • Open Values Format Registry draftThe list of every Open Values file format, one entry each: what the format is for, where its schema is, which files and code write it, which code reads it, and which checks enforce it.
  • Open Values Governance Ledger v0.1 draftThe file that holds every proposed change to the project's data and every public response to those proposals, kept at content/governance/proposals.json.
  • Open Values Presentation Page Kinds v1.0 draftThe ten kinds of page the shared page layer draws, each with its purpose, its main action, its sections in order, and the opening sentence for each coverage state.
  • Open Values Presentation Source Index v1.0 draftRecords for the sources that have their own page on the site, each with its publisher, dates, scope, limits and the catalogue facts that cite it.
  • Open Values Presentation Strings v1.0 draftThe words the shared page layer shows to readers: names for the main things a person works with, coverage messages, button labels and error messages.
  • Open Values Proposal v0.1 draftA suggested change to one data file, written down so anyone can read and check it: which file and version it changes, what it would change, why, and who wrote it.
  • Open Values Register Coverage Rules draftHand-reviewed rules saying which catalogue decisions each public register can supply facts for.
  • Open Values Register Entity Map draftFor one public register, which catalogue options have been matched to which company or record in that register, and which could not be matched.
  • Open Values Register Evidence Review draftThe record of a person checking the sample of entries in one evidence bundle against the register and the option mappings, and approving or rejecting it.
  • Open Values Register Shelf draftThe list of public registers, such as government recall and complaint databases, that this catalogue takes facts from, with how to fetch each one and the kinds of source it refuses.
  • Open Values Register Snapshot draftA record of one download from a public register: what was asked for, when, what came back, and a hash of the saved bytes so anyone can check they have not changed.
  • Conscious Consuming Taxonomy v1 draftThe full map of decisions the catalogue means to cover, in four levels from broad areas of life down to single decisions, with how many are built so far.
  • Open Values Value Editorial v0.4 draftThe sourced explanations shown on each value's page, such as Organic or Repairability: what the value requires, who checks it, where it stops and how the site uses it in scores.
  • Open Values Non-Brand Values v1 draftA list of words found in the brand field of options that are not brands, such as "generic" or "private messenger".

Published bundles

A file published for others to download and use.

  • Open Values Door v0.1 stableThe file a site publishes at /.well-known/open-values.json to say what it offers: which version of the standard it follows, its privacy promises, its licences, and every facts file it publishes with a hash to check it against.
  • Open Values Stack Index v0.1 stableA list of fixed copies of a site's facts files, each named by the SHA-256 hash of its contents, so a copy can be checked after download.

Files built from other files

A file a build step makes from other files. Change the sources, not this file.

  • Open Values Category Dataset v0.1 stableA built app-ready category dataset generated from a source lens or open-data pipeline.
  • Open Values Category Index v0.2 stableThe list of every live category on Conscious Consuming, such as coffee or banking, with its criteria, the human need it serves, and where its data file is, plus the full category tree and the data credit line.
  • Open Values Edges v0.1 stableA list of sourced links between options, brands and companies, such as which company owns a brand or which bank is an alternative to another.
  • Open Values Ask Core Index v0.1 stableThe small search index the app loads at startup for Ask, the site's search box.
  • Open Values Ask Index v0.1 stableThe full search index for Ask, the site's search box.
  • Open Values Avoid Token Index v0.1 stableFor each company a person can choose to avoid, the lowercase names of the company and the brands it owns, for matching against text on other web pages.
  • Open Values Node Index v0.1 stableA list of the things a reader can look up on the site besides single entries: brands, the companies that own them, labels such as "organic", and errands.
  • Open Values Node Manifest v0.1 stableA table of contents for the generated files in app/data/nodes: each file's name, size, hash and when to load it.
  • Open Values Pulse v0.1 stableThe list of recent changes to the catalogue: facts files and guides added or corrected, and facts files with sources old enough to need checking again.
  • Open Values Synonym Index v0.1 stableA lookup from everyday words people type, such as "oat milk", to the category or label on the site they mean.
  • Open Values Asks/Offers Index v0.1 draftA ready-to-show version of the asks and offers file, with each related category, guide and organisation looked up and filled in, plus counts and filter lists.
  • Open Values Challenge Index v0.1 draftA compact version of the challenge set for sites to read: each worked example with its top picks recomputed from the current category data and the chosen sourced facts filled in.
  • Open Values Design Token Index v0.1 draftA generated copy of the design tokens with CSS custom properties, computed colour contrast results, and counts of how many catalogue options can be drawn as a value bloom.
  • Open Values Governance Index v0.1 draftA summary of the governance ledger for the app to show: each proposal with whether its target file has changed since it was written, a tally of responses, and totals.
  • Conscious Consuming Map v1 draftEvery buying decision Conscious Consuming names, such as which plant-based milk or which bank, whether or not it has data yet, sorted into areas of life.
  • Open Values Presentation Package v1.0 draftOne generated file holding everything a site's page layer needs: the navigation tree with a route for every decision, the public wording, the ten page kinds, their test cases and the source index.
  • Open Values Register Coverage Matrix draftA generated table that gives every open or built decision a status against every register on the shelf: applicable, not applicable, blocked, or not yet reviewed.
  • Open Values Register Entity Inventory draftA list of every decision in the catalogue with how many options it has and a hash of their codes and names.
  • Open Values Register Evidence Bundle draftCitations ready to go into the catalogue, built from one register download, its matched options and its parsed facts, plus a sample of entries a person must check by hand.
  • Open Values Register Observations draftThe facts a parser read out of one saved register download, as short labelled values that each point back to the raw record they came from.

Parts of other formats

Not a file on its own: a shape used inside other formats.

  • Open Values Criterion v0.1 stableOne thing the options in a facts file are scored on, such as fossil-fuel financing or fees, with a key, a name and a note on how its scores were made.
  • Open Values Entity v0.1 stableOne option inside a facts file, such as a bank or a shampoo: its name, its scores from 0 to 100 on the file's criteria, and the source for each score.
  • Open Values Rating v0.1 stableOne option's score on one criterion, from 0 to 100.
  • Open Values Source v0.1 stableWhere a score comes from.

Test data and building contracts

Data kept for tests, not for use.

  • Open Values Conformance Vectors v0.1 draftA set of small example files for testing a reader or validator of Open Values formats.
  • Open Values Presentation Fixtures v1.0 draftTest cases for the shared page layer: for each of the ten page kinds, one real page with good sources, one with gaps, and one not covered yet, with what each page must and must not show.
  • Open Values Ask Fixtures v0.1 dev-contractTest searches for Ask, the site's search box, each with the results it must find and the order they must come in.
  • Open Values Ask Presentation Contract v0.1 dev-contractSuggested wording and grouping for showing Ask search results: section headings, labels for each kind of result, and what to offer when nothing matches.
  • Open Values Ask Traces v0.1 dev-contractFor each test search in ask-fixtures.json, the results the data build's own search gives, with scores and ranks, so the app's results can be compared against them.
  • Open Values Node Integration Checklist v0.1 dev-contractThe checklist for wiring the generated node and search files into the app: the phases of the work, the commands to run, and what must be true before each kind of page goes public.
  • Open Values Node Load Plan v0.1 dev-contractThe order in which the app should load the generated node and search files, what each stage needs, and what to do when a file fails to load.
  • Open Values Node Page Contracts v0.1 dev-contractFor each kind of page on the site (category, entry, guide, brand, company, label, errand, line), its address pattern, where its data comes from, which fields it needs, and the sections it shows.
  • Open Values Node Preview Matrix v0.1 dev-contractA list of test scenarios for a private preview of the app, grouped and in the order to run them, with what each must show.
  • Open Values Node Readiness v0.1 dev-contractA status report on the generated node and Ask search files: what the app loads and in what order, file sizes, and what must happen before each kind of page goes public.
  • Open Values Node Route Fixtures v0.1 dev-contractPage addresses that the site's address parser must understand, each with the result it must give.
  • Open Values Node Route Guardrails v0.1 dev-contractPage addresses that are broken, unsupported, point at nothing, or should be rewritten, with what the site must do for each.
  • Open Values Node Runtime States v0.1 dev-contractThe states the app can be in while loading the generated files, such as loading, unavailable or offline, with what the app must and must not do in each.
  • Open Values Node Walkthroughs v0.1 dev-contractWorked examples that follow one search, such as "is nestle bad", through to the company, brand and line pages it should open, with the checks each must pass.
