The appsThree apps on one scoring engine, and how to build a fourth.

Three apps that read the same values file

I built Conscious Consuming first, for everyday spending. Then I wanted to know whether the engine under it was general, or whether it only worked for shopping. So I built two more on the same code, one about learning and one about messaging, and changed only the facts and the look.

They work. Set your weights once and the same file ranks groceries, reading lists and messengers. This page shows what the three share, where they differ, and how to make a fourth.

What's happening. All three rank with the same scoring code, app/engine.js, and lay out their answers with the same decision page, app/decision.js. Each app owns one list of options and facts, and one stylesheet. Where to Message was built without a single edit to the shared files.

Why it matters. If the engine only worked for shopping, your values file would be a shopping file. Because it carries across subjects, the weights you set once can come with you into an app you have never opened, and a school or a co-op can build one without writing a scoring system of its own.

Devil's advocate. Three is a small number, and I built all three, so they share my blind spots. Two are demos. Where to Message ranks seven messengers on scores I assigned from public facts, and nobody outside this project has used a Kosplora route yet. What the three prove so far is that the engine works across subjects. They do not prove anyone else can build a fourth. That is the next test.

Rabbit hole. Open Where to Message's lens.js. It is one file of options, facts and value mappings, and it is the only code that app owns.

Plate IIFig. 2. What every app shares, and what each one can change.

What every app shares

An app can look and read like its subject. It cannot lock you in, sell a ranking or change the math. Two questions decide whether it belongs here: can your values file come in, and can anyone check and correct the facts?

Shared by all of them

  • The scoring engine. Weights, scores, bands, and combining a group's files.
  • The decision page. Sliders, ranked answers, the math behind each one, import and export.
  • The values file. One small file with your weights and no name in it.
  • The promises. No account, no tracking, no ads, and nobody pays to rank. It all runs in your browser.

Each app's own

  • The options and facts. What gets compared, with a source for each fact.
  • The criteria. Named in the subject's own words: "encryption", "rigor", "cost".
  • The look and the language. Kosplora is dark indigo; Where to Message is teal with a sans serif face.
  • The scope. What the app does not cover, stated on the page.

Before a new app is publicSix things that should be true before you share it.

What the next app needs first

A new app can look like anything. It still keeps the promises the other three keep: your values file works, the evidence can be checked, and nobody pays to rank.

  1. A plain decision. Name the real choice and who has to make it.
  2. Sourced facts. A source for every strong claim, a date on every fact, and a label on anything that is a judgement.
  3. Links back. To Values Commons, the values file, fact repair and the other apps.
  4. A values map. Say which of the ten shared values carry over, and which stay home.
  5. The same promises. No account, no tracking, no ads, no pay-to-rank, and it still works as plain files on a static host.
  6. An address for corrections. Show where a better source, a missing option or a whole replacement facts file should go.

New subject briefSix questions to answer in writing.

Write this before code

A clear decision and a small set of sourced facts will do more for an app than any interface. Answer these first. If one has no answer yet, start there.

  1. Decision. What real choice should this app help someone make?
  2. Audience. Who needs it first, and what words do they already use for it?
  3. Starter facts. Which 8 to 20 options and 3 to 7 criteria are enough to show it works?
  4. Values map. Which shared values carry over, and which should visibly stay home?
  5. Citations. Which claims need a citation before you would let a friend rely on it?
  6. Corrections. After launch, where do fixes, missing options, forks and disputes go?

Build the next app

An app is a folder. You write the facts file and the page; the engine and the shell are shared, and you link to them. Any static host is enough.

lens.js your facts + index.html your page + engine.js + shell.js

  1. Name the decision. Which options get ranked, and for whom?
  2. Source the facts. Each score needs a reason, a link and a date.
  3. Take values files in. Accept a file someone made elsewhere, and let them take it back out.
  4. Publish it as files. A folder on any static host runs the whole thing.
